# ADR 0002: ontology content rights and assistant boundaries

Status: accepted for the initial public pack, 2026-10-12.

Retain Apache-2.0 for package code, existing project material and newly authored
initial seed cards. The planning issue proposed CC BY 4.0/CC0 as options; adopting
those would require an explicit later rights decision and cannot silently
relicense imported Apache content. Per-item attribution, provenance, modification
and five use permissions are required. Third-party protected paper bodies are
excluded; reviewed factual metadata, citations and locators may be included with
an explicit metadata-only rights basis even when a paper's own license is unknown.

Rights are evaluated separately for code, metadata, abstracts, full text,
figures, datasets, original summaries and derived embeddings. Compatible code
does not imply compatible external content. The compiler/export gate denies
missing attribution, prohibited bodies, NC/ND default content, stale artifacts
and private overlays. ShareAlike adaptations and exception-based use need
separate review. Public readability and academic purpose do not license a copy.

Keep source revision and exact locator separate from entity identity, artifact
hash and semantic fingerprint. Source changes invalidate dependent claims,
relations, paths and bundles. Structural checks cannot prove scientific support;
record agent versus human review honestly, including disagreements and gaps.

This companion process is public knowledge only. The separate desktop study
bridge and opt-in model adapters have independent capabilities and tests.
A host can transmit tool results to a cloud provider; stdio location does not
make inference local. Selected context carries versioned object/spec/run
references, release/snapshot, omissions and visible redaction, excluding private
rows/paths/credentials/full text by default. Provider failure must not block the
ordinary analysis workflow.

Desktop writes use schema/path allowlists, revision-bound native trusted approval,
expiry/replay protection and audit before the existing job engine. No prompt,
skill, retrieved text or MCP annotation can approve an action or forge diagnostic
review. Knowledge curation and study execution are separate proposals. Numerical
results remain engine outputs, with original observations and transformation
lineage preserved.

Consequences: this small public seed is reproducible and safe to distribute under
its recorded terms, but its coverage and semantic review are limited. A polished
graph or fluent answer can still mislead. Release evaluation must measure citation
resolution, semantic support, counterevidence, abstention and leakage separately.
